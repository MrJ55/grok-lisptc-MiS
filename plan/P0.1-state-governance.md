# P0.1 — State Governance and Runtime Trust

**Status:** in progress (2026-09-04 — wave-2: form-by-form load, manifest validation, state/manifest.json, promote-candidate, ADR 0007)
**Depends on:** P0 solid (atomic save + form-by-form load done)
**Sources:** `review-by-all/02-TERRA-EXTENSIONS.md` §2.1–§2.3, §2.7; `review-by-all/05-UNIFIED-RECOMMENDATIONS.md` UR6, UR9 (full), UR12–UR15

## Goal

Establish the trust base: pin the upstream runtime, formalize provenance, separate content trust classes, add reality-status to every cognitive item, enforce capability governance, and make every durable mutation transactional, recoverable, and provenance-complete.

This phase is the prerequisite for any expansion of autonomous cognition (P7–P11). Do not start P7+ until P0.1 exit criteria pass.

## Objective

1. **Upstream lock** — `UPSTREAM.lock.json` with full commit SHA, content hashes, patch ID, capability profile, license.
2. **Hash verification** — `scripts/verify-upstream.sh` that fails closed on hash mismatch.
3. **Trust classes** — five-class taxonomy (untrusted / candidate / approved / derived / immutable) with promotion flow.
4. **Reality-status field** — every episode, chapter, and self-schema claim carries `:reality-status` from the enum `observed | reported | inferred | hypothesized | imagined | planned | simulated | retracted`.
5. **Compatibility manifest** — `*mind-manifest*` as the first form in `mind-image.ptc`; bridge validates it before evaluating the rest.
6. **Capability governance** — deny-by-default evaluator; explicit capability loading with declared profile, effect, scope, audit level, revocability.
7. **Transactional persistence** — prepare → validate → temp write → hash → atomic rename → verify reload; `state/manifest.json` + `state/audit/mutations.jsonl` + `state/checkpoints/last-known-good.ptc`.
8. **Operation event log** — every capability invocation recorded with operation_id, capability, effect_class, intent, arguments_hash, result_hash, status, checkpoints.
9. **Threat model** — `docs/threat-model.md` documenting attack surfaces (prompt injection via OSS output, supply chain via npm, Grok's Git write access, OSS text as Lisp injection vector).

## Implementation method

See sections A–H below. Wave-1 (2026-09-04): docs, manifest form, reality-status audit, OSS-shape prevalidate, LKG + mutations journal. Wave-2: form-by-form load + manifest check, `state/manifest.json`, `(promote-candidate)`, ADR 0007.

### A. Upstream lock (UR6)

`UPSTREAM.lock.json` and `scripts/verify-upstream.sh` exist. Bootstrap still fetches missing `src/lisp.ts` at the pinned commit. Full vendoring of `lisp.ts` into the repo remains a follow-up (verify-upstream currently requires the file present).

### B. Trust classes (UR12)

Documented in `docs/trust-classes.md` + ADR 0006. `prevalidate` rejects common OSS-shaped prose. `(promote-candidate candidate-id)` returns a host-mediated promotion reminder (does not auto-elevate trust).

### C. Reality-status field (UR13)

Episodes and chapters carry `:reality-status`. `dmn-log-episode` defaults missing status to `observed`. `(audit-reality-status)` returns episodes still missing the field. Existing OSS episodes tagged `imagined`.

### D. Compatibility manifest (UR15)

`*mind-manifest*` is the first form in `mind-image.ptc`. Bridge extracts top-level forms and loads form-by-form; after the first form it checks that `*mind-manifest*` is bound and mentions a known schema. `--strict-load` fails the process on missing/invalid manifest or form failures.

### E. Capability governance (UR14)

Deny-by-default documented (`extensions: []`). Profiles in `docs/capability-governance.md`. ADR 0007 accepted. No capability load/unload helpers yet (first load expected in P5).

### F. Transactional persistence (UR9 full)

Atomic temp+rename append remains. On every `--save`: refresh `state/checkpoints/last-known-good.ptc`, append a mutation record to `state/audit/mutations.jsonl`, and rewrite `state/manifest.json` (schema version, image hashes, last mutation ID). Crash-injection tests still open.

### G. Operation event log (UR14 sub)

Deferred until first external capability (P5). Schema reserved in `state/README.md`.

### H. Threat model

`docs/threat-model.md` covers the six primary surfaces.

## Exit criteria
- `bash scripts/verify-upstream.sh` exits 0 on a clean clone (with sources present).
- `bash scripts/smoke-test.sh` exits 0 including `(dmn-reflect-pack 5)`, `(audit-reality-status)`, and `(promote-candidate 'demo)`.
- A crash mid-save leaves either the prior valid state or the new state — never partial.
- `last-known-good.ptc` is bootable after any failed `--save`.
- Every episode, chapter, and self-schema claim has a `:reality-status` field.
- `*mind-manifest*` is present and validated on every load.
- No untrusted content (OSS output, transcript, retrieved memory) is evaluated as Lisp.
- Threat model is documented; each attack surface has a mitigation owner.

## Non-goals (this phase)
- Vestige integration (P5)
- Protocol registry (P11 evolution)
- Full capability implementation (only the framework + deny-by-default)
- Automatic promotion of candidates (still Grok-mediated)

- **P1 (vendoring) should be done in parallel** — `UPSTREAM.lock.json` needs vendored `src/lisp.ts`.
- **P2–P4 are paused** until P0.1 exit criteria pass (the pause + fix sprint from GLM).
- **P6 (evaluation) is elevated** to immediately after P0.1, before P7–P11 expansion.
