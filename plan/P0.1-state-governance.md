# P0.1 — State Governance and Runtime Trust

**Status:** exit criteria substantially met (2026-09-04 — wave-3: CI + crash/malicious tests + vendor verify)
**Depends on:** P0 solid (atomic save + form-by-form load done)
**Sources:** `review-by-all/02-TERRA-EXTENSIONS.md` §2.1–§2.3, §2.7; `review-by-all/05-UNIFIED-RECOMMENDATIONS.md` UR6, UR9 (full), UR12–UR15

## Goal

Establish the trust base: pin the upstream runtime, formalize provenance, separate content trust classes, add reality-status to every cognitive item, enforce capability governance, and make every durable mutation transactional, recoverable, and provenance-complete.

This phase is the prerequisite for any expansion of autonomous cognition (P7–P11). Do not start P7+ until P0.1 exit criteria pass.

## Objective

1. **Upstream lock** — `UPSTREAM.lock.json` with full commit SHA, content hashes, patch ID, capability profile, license.
2. **Hash verification** — `scripts/verify-upstream.sh` that fails closed on hash mismatch.
3. **Trust classes** — five-class taxonomy (untrusted / candidate / approved / derived / immutable) with promotion flow.
4. **Reality-status field** — every episode, chapter, and self-schema claim carries `:reality-status` from the enum `observed | reported | inferred | hypothesized | imagined | planned | simulated | retracted`.
5. **Compatibility manifest** — `*mind-manifest*` as the first form in `mind-image.ptc`; bridge validates it before evaluating the rest.
6. **Capability governance** — deny-by-default evaluator; explicit capability loading with declared profile, effect, scope, audit level, revocability.
7. **Transactional persistence** — prepare → validate → temp write → hash → atomic rename → verify reload; `state/manifest.json` + `state/audit/mutations.jsonl` + `state/checkpoints/last-known-good.ptc`.
8. **Operation event log** — every capability invocation recorded with operation_id, capability, effect_class, intent, arguments_hash, result_hash, status, checkpoints.
9. **Threat model** — `docs/threat-model.md` documenting attack surfaces (prompt injection via OSS output, supply chain via npm, Grok's Git write access, OSS text as Lisp injection vector).

## Implementation method

Wave-1: docs, manifest form, reality-status audit, OSS-shape prevalidate, LKG + mutations journal.  
Wave-2: form-by-form load + manifest check, `state/manifest.json`, `(promote-candidate)`, ADR 0007.  
Wave-3: CI workflow, crash-recovery test, malicious-PTC test, verify-upstream auto-heal + hash fail-closed.

### A. Upstream lock (UR6)

`UPSTREAM.lock.json` pins commit + content hashes. `scripts/verify-upstream.sh` auto-heals incomplete vendor (missing / empty / `VENDOR_STUB` / hash mismatch) by re-fetching the pinned upstream blob, then fails closed if hashes still mismatch. Works with `jq` or pure Python.

### B–H

Unchanged from wave-2 (trust classes, reality-status, manifest, capability governance, transactional persistence, threat model).
