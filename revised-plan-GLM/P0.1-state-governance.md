# P0.1 — State Governance and Runtime Trust

**Status:** new (added 2026-09-04 — GLM+Terra synthesis)
**Depends on:** P0 solid (atomic save + form-by-form load done)
**Sources:** `review-by-all/02-TERRA-EXTENSIONS.md` §2.1–§2.3, §2.7; `review-by-all/05-UNIFIED-RECOMMENDATIONS.md` UR6, UR9 (full), UR12–UR15

## Goal

Establish the trust base: pin the upstream runtime, formalize provenance, separate content trust classes, add reality-status to every cognitive item, enforce capability governance, and make every durable mutation transactional, recoverable, and provenance-complete.

This phase is the prerequisite for any expansion of autonomous cognition (P7–P11). Do not start P7+ until P0.1 exit criteria pass.

## Objective

1. **Upstream lock** — `UPSTREAM.lock.json` with full commit SHA, content hashes, patch ID, capability profile, license.
2. **Hash verification** — `scripts/verify-upstream.sh` that fails closed on hash mismatch.
3. **Trust classes** — five-class taxonomy (untrusted / candidate / approved / derived / immutable) with promotion flow.
4. **Reality-status field** — every episode, chapter, and self-schema claim carries `:reality-status` from the enum `observed | reported | inferred | hypothesized | imagined | planned | simulated | retracted`.
5. **Compatibility manifest** — `*mind-manifest*` as the first form in `mind-image.ptc`; bridge validates it before evaluating the rest.
6. **Capability governance** — deny-by-default evaluator; explicit capability loading with declared profile, effect, scope, audit level, revocability.
7. **Transactional persistence** — prepare → validate → temp write → hash → atomic rename → verify reload; `state/manifest.json` + `state/audit/mutations.jsonl` + `state/checkpoints/last-known-good.ptc`.
8. **Operation event log** — every capability invocation recorded with operation_id, capability, effect_class, intent, arguments_hash, result_hash, status, checkpoints.
9. **Threat model** — `docs/threat-model.md` documenting attack surfaces (prompt injection via OSS output, supply chain via npm, Grok's Git write access, OSS text as Lisp injection vector).

## Implementation method

### A. Upstream lock (UR6)

Create `UPSTREAM.lock.json`:
```json
{
  "lisptc_repository": "https://github.com/1hachem/lisptc",
  "lisptc_commit": "2c10ea8ed6edb16e065b746a7f52080956b895de",
  "lisp_source_path": "packages/interpreter/src/lisp.ts",
  "arith_source_path": "packages/interpreter/src/arith.ts",
  "lisp_source_sha256": "<hash of vendored src/lisp.ts>",
  "arith_source_sha256": "<hash of vendored src/arith.ts>",
  "patch_id": null,
  "patched_sha256": null,
  "license": "MIT",
  "capability_profile": "mind-sandbox-v1",
  "acquired_at": "2026-09-04T00:00:00Z"
}
```

Create `scripts/verify-upstream.sh`:
```bash
#!/usr/bin/env bash
set -euo pipefail
EXPECTED_LISP=$(jq -r .lisp_source_sha256 UPSTREAM.lock.json)
EXPECTED_ARITH=$(jq -r .arith_source_sha256 UPSTREAM.lock.json)
ACTUAL_LISP=$(sha256sum src/lisp.ts | cut -d' ' -f1)
ACTUAL_ARITH=$(sha256sum src/arith.ts | cut -d' ' -f1)
[[ "$EXPECTED_LISP" == "$ACTUAL_LISP" ]] || { echo "FAIL: src/lisp.ts hash mismatch"; exit 1; }
[[ "$EXPECTED_ARITH" == "$ACTUAL_ARITH" ]] || { echo "FAIL: src/arith.ts hash mismatch"; exit 1; }
echo "OK: upstream sources match lock file"
```

### B. Trust classes (UR12)

Five-class taxonomy:

| Class | Examples | Mutation route | Validation |
|---|---|---|---|
| **untrusted** | transcript text, OSS output, retrieved memory content | never evaluated as Lisp | schema check on ingest |
| **candidate** | parsed proposal awaiting validation | stored in `mind/oss-proposals-*.ptc`, not in `mind-image.ptc` | schema + provenance + contradiction check |
| **approved** | Grok-authored Lisp that passed `prevalidate` + `eval` | `--save` to `mind-image.ptc` | eval success |
| **derived** | narrative, session prompt, mind projection | generated from approved state | rebuild from source |
| **immutable** | append-only event record, released checkpoint provenance | append-only journal | hash chain |

Promotion flow:
```
reflection/wander/OSS/transcript
  → candidate event, episode, claim, procedure, or narrative fragment
  → schema + size + provenance + contradiction + capability checks
  → approval/rejection/defer
  → approved state mutation or trusted MiS code change
  → projection rebuild and reload verification
```

Implementation:
- `bridge/eval.ts` `prevalidate` extended to reject strings that look like OSS output (heuristic: contains known nudge-craft prefixes like "I am the transcript").
- New Lisp helper `(promote-candidate candidate-id)` that validates and applies a candidate from `oss-proposals-*.ptc`.
- `docs/trust-classes.md` documents the taxonomy and promotion flow.
- `adr/0006-trust-classes.md` records the decision.

### C. Reality-status field (UR13)

Extend the episode record, chapter record, and self-schema claim to require `:reality-status`:

```lisp
;; Episode record (extended)
(dmn-log-episode input result meta)
;; where meta includes (:reality-status . observed|reported|inferred|hypothesized|imagined|planned|simulated|retracted)

;; Chapter record (extended)
(dmn-chapter-close title summary refs)  ;; adds (:reality-status . observed) by default

;; Self-schema claim (extended)
(update-self-schema alist)
;; where each claim can be (:working-insights . (...)) with reality-status tags
```

Eight values:
- `observed` — something that actually happened (e.g., "host restored image")
- `reported` — something the user said
- `inferred` — something Grok concluded from evidence
- `hypothesized` — something proposed as a possibility
- `imagined` — OSS-generated or model-generated content
- `planned` — a future intention
- `simulated` — a counterfactual or prospection result
- `retracted` — a previously held belief now withdrawn

Migration: tag existing episodes retroactively:
- OSS-sourced entries (`:source oss-dmn`) → `:imagined`
- Hardcoded `*self-schema*` defaults → `:observed` or `:inferred`
- *Genesis of GMOD* chapter → `:observed` (the host restoration) with `:imagined` sub-elements (the OSS line)

Audit helper:
```lisp
(defun audit-reality-status ()
  "Return list of items with missing or inconsistent reality-status."
  (let ((issues nil))
    (dolist (ep *episodic-buffer*)
      (let ((meta (caddr ep)))
        (unless (and (consp meta) (assoc :reality-status meta))
          (setq issues (cons (list 'episode ep) issues)))))
    issues))
```

### D. Compatibility manifest (UR15)

First form in `mind-image.ptc`:
```lisp
(setq *mind-manifest*
  '((:gmod-schema . "0.1.0")
    (:helpers-version . "0.3")
    (:lisptc-commit . "2c10ea8ed6edb16e065b746a7f52080956b895de")
    (:lisptc-source-sha256 . "<hash>")
    (:capability-profile . "mind-sandbox-v1")
    (:created-at . "2026-09-02T00:00:00Z")))
```

`bridge/eval.ts` `loadImage`:
1. Eval the manifest form first (extract `*mind-manifest*`).
2. Check `:gmod-schema` against a known version list (`["0.1.0"]`).
3. Check `:lisptc-commit` against `UPSTREAM.lock.json`.
4. Warn (or fail with `--strict-load`) on mismatch.
5. Only then eval the rest of the image.

### E. Capability governance (UR14)

Deny-by-default evaluator. Capabilities are absent unless explicitly loaded.

Capability profiles (design only — no capabilities loaded yet):

| Profile | Permitted purpose | Authorization |
|---|---|---|
| `mind-read-v1` | Safe project inspection | Automatic |
| `mind-memory-read-v1` | Vestige recall, graph, causal backfill | Automatic |
| `mind-candidate-write-v1` | Bounded candidate creation | Policy-gated |
| `reflection-v1` | Read, compute, candidate claims/procedures | No direct promotion |
| `vestige-maintenance-v1` | Consolidation, dedup, suppression | Explicit policy |
| `git-governed-write-v1` | Approved repository writes | User confirmation |
| `secrets-v1` | Sensitive credential resolution | Explicit elevated grant |
| `external-action-v1` | Remote side effects | User confirmation |

Every loaded binding declares: name, profile, effect (read/write), scope, input/output schemas, audit level, confirmation rule, revocability.

When the first capability is loaded (likely Vestige in P5), implement:
- `CapabilityDescriptor` schema
- `mind-load-capability`, `mind-unload-capability`, `mind-capabilities`, `mind-execute` Lisp helpers
- `adr/0007-capability-governance.md`

### F. Transactional persistence (UR9 full)

Replace `appendTranscript` with a transaction:

```
prepare → validate → write temp artifact → hash → atomic rename → verify reload
```

State:
- `state/manifest.json` — current state manifest (schema version, image hash, last mutation ID, checkpoint ref)
- `state/checkpoints/last-known-good.ptc` — automatic fallback
- `state/checkpoints/last-known-good.manifest.json` — fallback manifest
- `state/audit/mutations.jsonl` — append-only journal

Every mutation records:
```json
{
  "mutation_id": "mut-<uuid>",
  "actor": "grok-session-<id>",
  "timestamp": "ISO-8601",
  "operation": "append-forms",
  "input_forms_hash": "sha256:...",
  "state_before_hash": "sha256:...",
  "state_after_hash": "sha256:...",
  "validation_result": "success",
  "rollback_target": "mut-<prev-uuid>"
}
```

### G. Operation event log (UR14 sub)

When capabilities are loaded, every invocation creates an operation event:
```json
{
  "operation_id": "op-<uuid>",
  "parent_operation_id": null,
  "session_id": "session-<id>",
  "mind_checkpoint_before": "ckpt-<id>",
  "started_at": "ISO-8601",
  "capability": "vestige/backfill",
  "effect_class": "read",
  "intent": "Trace causal predecessors of state regression.",
  "arguments_hash": "sha256:...",
  "result_hash": "sha256:...",
  "result_summary": "bounded non-sensitive summary",
  "status": "success|failure|denied",
  "finished_at": "ISO-8601",
  "mind_checkpoint_after": "ckpt-<id>",
  "reality_status": "observed"
}
```

Stored in `state/audit/operations.jsonl`. Subsumes `mind-failures.log` (which becomes a filtered view of operations with `status: failure`).

### H. Threat model

Create `docs/threat-model.md` documenting:
1. **Prompt injection via OSS output** — OSS-generated text stored as Lisp string literals in `*episodic-buffer*` / `*autobiography*`. If OSS output contains a string that breaks the reader, it corrupts the image on load. Mitigation: schema-validate OSS output before storing; never store raw OSS text as a Lisp string literal without escaping.
2. **Supply chain via npm** — `zod` is fetched from public registry with no integrity check. Mitigation: pin `zod` version, use `npm ci` with `package-lock.json`, consider `npm audit` in CI.
3. **Supply chain via upstream** — `src/lisp.ts` was previously curled from `main` with no hash. Mitigation: vendored + `UPSTREAM.lock.json` + `verify-upstream.sh` (this phase).
4. **Grok's Git write access** — `skills/mis-save/SKILL.md` instructs Grok to commit/push. Risk: Grok commits malicious or buggy content. Mitigation: require human review of Grok-authored commits; CI smoke test on every push.
5. **Attribution drift** — fork's `arith.ts` claims "derive from" upstream but is a rewrite. Mitigation: revert to upstream verbatim (P1), restore attribution.
6. **Grok mutates docs** — `CUSTOM_INSTRUCTIONS.md` line 27 tells Grok to append to `docs/learnings-log.md`. Risk: Grok rewrites governance docs to justify future mutations. Mitigation: docs are `derived` trust class; governance docs (ADRs, plan/) require human review.

## Exit criteria
- `bash scripts/verify-upstream.sh` exits 0 on a clean clone.
- `bash scripts/smoke-test.sh` exits 0 including `(dmn-reflect-pack 5)`.
- A crash mid-save leaves either the prior valid state or the new state — never partial.
- `last-known-good.ptc` is bootable after any failed `--save`.
- Every episode, chapter, and self-schema claim has a `:reality-status` field.
- `*mind-manifest*` is present and validated on every load.
- No untrusted content (OSS output, transcript, retrieved memory) is evaluated as Lisp.
- Threat model is documented; each attack surface has a mitigation owner.

- Full capability implementation (only the framework + deny-by-default)
